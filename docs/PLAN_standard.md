# План: звичайна клавіатура, тогл, скрін, повзунки, exe

Створено 2026-11-14. Мета — зробити оптимізатор корисним для людей без
спліта і без Claude Code: розкладка для звичайної (сходинкової) ANSI-клавіатури,
перемикач режиму в GUI, кнопка скріна, повзунки впливу на ваги, експорт
розкладки в ОС і збірка exe для Windows.

Кожна фаза — окрема гілка/PR, стекований на попередню. Прогрес відмічати
тут (`[x]`) і в `docs/WORKLOG.md`.

## Ухвалені рішення (автор, 2026-11-14)

1. **Геометрія — ANSI** (українська клавіатура ЙЦУКЕН на ANSI-платі).
2. **Слоти для літер — ті самі клавіші, що й у ЙЦУКЕН**, плюс `\` (там ґ, як
   у Ukrainian Enhanced). Тобто оптимізатор переставляє літери лише всередині
   ЙЦУКЕН-слотів; цифровий ряд і решта — не чіпаємо.
3. **Дублі для зручності**: на клавіші з `і` через AltGr — `ї`, на клавіші з
   `г` через AltGr — `ґ` (як у Ukrainian Enhanced). Це лише для експорту в ОС
   (фаза 5); в оцінці AltGr-дублі не враховуються — основне місце літери
   оптимізується як звичайно.
4. **Близькість до ЙЦУКЕН** — окремий повзунок (фаза 4), а не жорстке
   обмеження: штраф за кожну літеру не на своєму ЙЦУКЕН-місці.
5. **«Більше вертикальних»** = менший штраф за **same-finger біграми по
   вертикалі** (`same_finger.vertical`), а не за переходи між рядами загалом.
6. **Enter не оцінюємо взагалі.** Частота `'\n'` у корпусі неадекватна:
   Telegram-новини, чати, розмовний стиль у книжках — переноси рядків там
   довільні. Біграми з `'\n'` викидаються з оцінки в обох режимах.
   Клавіша Enter на сітці — лише для вигляду (заблокована).
7. **Пробіл і шифт** — фіксовані клавіші, які **беруть участь** в оцінці
   (не переставляються). Пробіл — великий палець; шифт — акорд мізинцем
   (див. фазу 2).
8. **Windows-тест** — автор має доступ до Windows-машин і тестує сам.
9. **Крапка і кома — повноправні учасники**: переставляються мутатором і
   оцінюються скорером, як літери (кома в корпусі — одна з найчастіших).
10. **Апостроф** — оцінюється з урахуванням його рідкісності; з'ясувати, чи
   вигідніше поставити його ближче, навіть на AltGr-шар (AltGr = правий Alt,
   великий палець), ніж на окрему далеку клавішу.

**Наслідок 9–10 для слотів.** Переставних клавіш: 33 ЙЦУКЕН-слоти літер
(з `\`) + `/` = 34; символів: 33 літери + `.` + `,` = 35 (+ `'`). Кома
отримує власну клавішу (не Shift+`/`), тож потрібен ще слот: кандидат —
`` ` `` (лівий верхній кут, далеко — скорер сам туди витисне найрідшу).
Апостроф — два варіанти, порівняти скором:
  а) окрема клавіша (тоді слотів бракує — довелося б брати `` ` `` і
     перенести кому/крапку… або цифровий ряд — ні, рішення 2);
  б) AltGr-шар над будь-якою клавішею: штраф = акорд великого пальця
     (правий Alt) + клавіша; хост вибирає скорер (перебір усіх клавіш при
     фіксованій розкладці, або як окремий «віртуальний» слот у мутаторі).
  Апостроф іде після б/п/в/м/ф/р («пʼять», «мʼясо») — врахувати ці біграми.

## Що є зараз (стан коду на 2026-11-14)

- `core/scorer.py` бачить лише `row` / `col` / `home_col` / палець; поле
  `offset_x` у `geometry.json` (стаггер) **ніде не читається**.
- `generic_105_alpha` у `geometry.json` — заготовка ЙЦУКЕН: 38 позицій,
  зсуви рядів 0/15/45 px при `key_width` 50 (реальний ANSI: 0 / 0.25u / 0.75u
  = 0 / 12.5 / 37.5 px) — перевірити й виправити.
- `statistic.json` — у нижньому регістрі (великих літер нема → шифт не
  оцінити без перерахунку). `' '` і `'\n'` є, але `SPA`/`CE` на розкладці
  мають `role: mod` → їхні n-грами зараз відкидаються.
- Геометрія вибирається раз при імпорті (`config/main_config.py`,
  `active_layout`), engine будує таблиці в `__init__`.
- `export_svg()` у `uiux/app.py` — порожня заглушка.
- Перешкоди для exe: шляхи через `PROJ_DIR`, запис `recorded_layout.json` у
  теку проєкту, ZMK/pyserial-функції, зламаний `main.py`.

## Фаза 2 — модель і розрахунок для звичайної клавіатури (п. 1)

1. [ ] **Геометрія ANSI**: виправити зсуви рядів (0 / 0.25u / 0.75u),
       перевірити призначення пальців (стандартне сенсорне: ліва Я — мізинець,
       права `.` — мізинець, `[ ] \ '` — правий мізинець), позначити рівно
       ЙЦУКЕН-слоти + `\` + `/` + `` ` `` як переставні; цифри — фіксовані;
       `.` і `,` — окремі символи в пулі мутатора (рішення 9).
1a. [ ] **Апостроф** (рішення 10): AltGr-шар у моделі (акорд правого Alt +
       клавіша-хост), порівняти варіанти а/б зі списку слотів вище; лишити
       кращий. В експорті (фаза 5) — на вибраному місці.
2. [ ] **Стаггер у моделі**: фізичні координати (x з урахуванням зсуву ряду).
       - same-finger: штраф за відстанню (Й→Я на стаггері — діагональ, довша
         за вертикаль на спліті);
       - множник лівого нижнього ряду (кут зап'ястя) окремо від правого;
       - розтяг (`stretch`) — за реальною відстанню колонок.
       На `corne_42` зсувів нема → скори спліта мають лишитись **ідентичними**
       (перевірка: переоцінка розкладок k/l/m/n до і після).
       Після змін — `scripts/check_delta.py`.
3. [ ] **Пробіл** як фіксована клавіша великого пальця в оцінці (переходи
       літера↔пробіл; `hand_runs` уже ділить по словах — не задвоїти).
4. [ ] **Шифт**: перерахувати частку великих літер на вибірці корпусу
       (окремий скрипт, під `cpulimit -l 60`, результат — кілька КБ: частка
       великих по кожній літері). Оцінка: велика літера = акорд мізинця з
       шифтом; на тій самій руці, що й шифт, — дорожче (протилежний шифт —
       норма).
5. [ ] **Базова точка — ЙЦУКЕН**: скор стандартної розкладки як еталон;
       у GUI/скріні — «на X% менше штрафу, ніж ЙЦУКЕН».
6. [ ] Прогони: `scripts/multistart.py` для `generic_105_alpha` під cpulimit,
       по одному. Перевірки: голосні на обох руках, мізинці ≤ ~10%,
       чергування рук ~50–55%, перекати сусідніми ≥ ~23%.
7. [ ] 2–3 кандидати автору — картинками з фази 1. Обирає автор;
       найкраща стає дефолтною для режиму «Звичайна».

## Фаза 4 — повзунки впливу (п. 5)

Не повернення старих слайдерів окремих ваг, а 4–6 високорівневих ручок;
кожна множить групу ваг у межах ×0.5…×1.5 (або 0…max для нових штрафів).

| Повзунок | Що крутить |
|---|---|
| Більше домашнього ряду | `row_multiplier.home_row` ↓ (часті літери шикуються вздовж домашнього ряду) |
| Більше вертикальних SFB | `same_finger.vertical` ↓ (рішення 5) |
| Менше мізинців | `column_multiplier.col_pinky`, `finger_multiplier.pinky` ↑, `finger_load.cap.pinky` ↓ |
| Чергування рук ↔ перекати | `hand_runs.*` проти `finger_alternation.brother_finger` / `roll_rows.natural_arc` |
| Близькість до ЙЦУКЕН | новий штраф за літеру не на своєму ЙЦУКЕН-місці (рішення 4); лише в режимі «Звичайна» |

- [ ] Нова вага близькості — у `moves_standard.yaml` з коментарем + схема.
- [ ] Engine перебудовується **після відпускання** повзунка (таблиці
      будуються в `__init__`), не на кожен рух.
- [ ] Панель метрик поруч: чергування %, голосні Л/П, мізинці %, SFB %,
      «vs ЙЦУКЕН» — щоб юзер бачив, коли ручка ламає розкладку (усі голосні
      на одній руці = регрес).
- [ ] «Скинути до рекомендованих», збереження пресета в юзерську теку.
- [ ] Повзунки працюють в обох режимах (кожен режим — свої базові ваги).

## Фаза 6 — збірка exe (п. 3)

- [ ] PyInstaller, режим `onedir` (швидший старт, менше хибних спрацювань
      антивірусів, ніж `onefile`); конфіги й статистика (~2.6 МБ) — ресурси
      через `sys._MEIPASS`-сумісний резолвер шляхів.
- [ ] ZMK/pyserial — не включати в exe (або імпорт за запитом і сховано).
- [ ] GitHub Actions `windows-latest` → артефакт `.zip`, реліз за тегом
      (з Linux exe для Windows нормально не зібрати).
- [ ] Tk на Windows: шрифти (`FONT`), DPI-масштабування; оптимізатор не
      вантажить CPU на 100% (менший пріоритет / потоки).
- [ ] Автор тестує на Windows-машині; чекліст: запуск, тогл, Start/Stop,
      скрін, повзунки, експорт `.klc`.
